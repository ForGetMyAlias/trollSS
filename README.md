## Ключевые особенности

- **Без сигнатур**: самописный чит не имеет известного имени, поэтому сканер смотрит на то, что остаётся после инжекта: класс которого нет ни в одном jar, библиотека загруженная и сразу удалённая, нативный код который сам ищет JVM.
- **Изнутри JVM**: список всех загруженных классов, загрузчики, границы JIT кэша и стеки потоков берутся через сокет attach (протокол jcmd), JDK не нужен.
- **Только чтение**: ничего не запускает, не пишет на диск и не меняет на ПК. Единственный след это сокет `.java_pid`, его можно отключить флагом `--passive`.
- **Настоящий прогресс**: проценты на экране считаются по реальной работе (прочитанным байтам и jar), а не по таймеру.
- **Отчёт для машины**: результат пишется в JSON, код выхода говорит есть ли критические находки.
- **Расширяется одним файлом**: новая проверка это новый модуль и одна строка в реестре.

## Структура проекта

```tree
trollss/
├── assets/
│   └── troll.png             # Картинка для экрана сканирования
├── src/
│   ├── main.rs               # Поиск игры, запуск проверок, вывод и код выхода
│   ├── model.rs              # Finding, Sev, Ctx, трейт Check, разбор /proc/PID/maps
│   ├── ui.rs                 # Экран: картинка, SCANNING и процент
│   └── checks/
│       ├── mod.rs            # Реестр проверок
│       ├── maps.rs           # Память без файла, удалённые и чужие библиотеки
│       ├── agent.rs          # Агенты, JVMTI, нативный код ищущий JVM
│       ├── integrity.rs      # Код в памяти против файла на диске
│       ├── classes.rs        # Классы в памяти против всех jar
│       ├── jvm.rs            # Классы, загрузчики, JIT и стеки через attach
│       ├── tracing.rs        # ptrace, запись в память игры, скрытые процессы
│       ├── mods.rs           # Структура и содержимое jar в mods/
│       ├── launch.rs         # Как запустили JVM: preload, флаги
│       ├── traces.rs         # Корзина, история, журнал
│       ├── sysenv.rs         # Виртуалка, контейнер, Wine, VPN, хотспот
│       └── bypass.rs         # Фейковый ввод, удалёнка, песочницы, время
├── Cargo.toml
├── LICENSE
└── README.md
```

## Быстрый старт

### 1. Сборка

Нужен Rust со стабильным `cargo` 1.85 или новее.

```bash
cargo build --release
```

### 2. Запуск

Запускать с `root` пока Minecraft открыт: без игры проверки процесса пропускаются, без root недоступна память чужих процессов.

```bash
sudo ./target/release/trollss
```

Экран с анимацией выглядит нормально в `ghostty` и `kitty`, в остальных терминалах картинка рисуется блоками.

### 3. Флаги

| Флаг | Описание |
| :--- | :--- |
| `--no-ui` | Без анимации, находки печатаются в терминал |
| `--json FILE` | Куда сохранить отчёт, по умолчанию `trollss-report.json` |
| `--passive` | Не подключаться к JVM, остаются только проверки по `/proc` |
| `-h`, `--help` | Справка |

### 4. Код выхода

| Код | Значение |
| :--- | :--- |
| `2` | Есть критические находки |
| `1` | Только предупреждения |
| `0` | Находок нет |

## Проверки

| Проверка | Что ищет | Как |
| :--- | :--- | :--- |
| **maps** | Код без файла, загруженные и удалённые библиотеки, исполняемая память вне JIT | `/proc/PID/maps` |
| **agent** | Агенты на лету, JVMTI, нативный код который сам ищет JVM, Rust-сборка | Разбор ELF, `libinstrument` без `-javaagent` |
| **integrity** | Хуки и патчи в `libjvm`, `libc` и других | Страницы в памяти против файла |
| **classes** | Классы которых нет ни в одном jar, jar добавленный после запуска | Поиск `CAFEBABE` в памяти, сверка с jar |
| **jvm** | Неизвестные классы и загрузчики, чужой код на стеках потоков | Сокет attach (`VM.class_hierarchy`, `Compiler.codecache`) |
| **tracing** | ptrace, запись в память игры, скрытые процессы и модули ядра, слушающие порты | `/proc`, `/sys/module` |
| **mods** | Агент в манифесте, нативка, обфускация, запуск процессов, названия читерских модулей, мод добавленный на ходу | Структура и константы классов |
| **launch** | `LD_PRELOAD`, подозрительные флаги JVM, временные папки в аргументах | cmdline, environ |
| **traces** | Следы зачистки: корзина, история shell, журнал | Файлы домашней папки, `journalctl` |
| **sysenv** | Виртуалка, контейнер, Wine, VPN, раздача интернета (хотспот, модем) | `/sys`, `/proc`, `iw`, `nmcli` |
| **bypass** | Фейковый ввод (`uinput`), удалёнка, песочницы, трюки со временем, замаскированные jar, обёртки лаунчера, eBPF | `/proc`, конфиги лаунчеров |

Как добавить свою: создай файл в `src/checks/`, реализуй трейт `Check` и добавь одну строку в `src/checks/mod.rs`.

## Приватность и побочные эффекты

> Сканер читает память и список процессов, историю команд shell, корзину, системный журнал, файлы в папке игры и в домашней папке, содержимое jar. **Ничего не отправляется по сети**, отчёт остаётся на диске. Запускай его только на ПК, где владелец согласен на проверку.

- Подключение к JVM оставляет сокет `/tmp/.java_pid<PID>` и шлёт игре `SIGQUIT`. `--passive` это отключает.
- Без root часть проверок пропускается: память чужих процессов, анализ удалённых библиотек, стеки потоков.

## Ограничения

Отсутствие находок не значит, что система чистая.

- **Не видно**: читы на уровне ядра и гипервизора, DMA и железо, инжект который убрал за собой все следы.
- **Forge**: пакет `net/minecraft/*` пропускается при поиске классов, потому что Forge переименовывает их на ходу. Чит спрятанный в этом пакете пройдёт.
- **Ложные срабатывания**: пороги и словари подобраны на глаз, проверялось на одной системе (Arch, ghostty). Часть проверок (хотспот, мод добавленный на ходу, стеки потоков) проверена только компиляцией и логикой.
